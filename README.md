# 🎂 ربات تولد و پنل مدیریت

نسخه اصلی با `aiogram` اجرا می‌شود. تاریخ‌ها شمسی و مبنای روز/ساعت، `TIMEZONE` (پیش‌فرض تهران) است.

## اجرای لوکال

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
.venv/bin/python main.py
```

در `.env` مقدار `BOT_TOKEN` و آیدی عددی مالک در `ADMIN_IDS` را قرار دهید. دستور `/id` شناسه خودتان را نمایش می‌دهد. توکن را منتشر نکنید. اگر وب‌هوک فعالی وجود داشته باشد، برنامه با توضیح متوقف می‌شود و آن را خودکار حذف نمی‌کند.

## انتقال بات، دیتابیس و مینی‌اپ به Linux VPS

بات، SQLite، API و فایل‌های مینی‌اپ همگی روی VPS می‌مانند. `webapp_api.py` همان پوشهٔ `webapp` را سرو می‌کند و API را در همان مبدأ ارائه می‌دهد؛ مینی‌اپ برای پروفایل و تولدهای عزیزان به تونل یا URL جداگانه نیاز ندارد. Nginx فقط HTTPS را به برنامهٔ محلی روی `127.0.0.1:8080` می‌رساند.

### ۱. آماده‌سازی فایل‌های VPS

نمونهٔ زیر برای Ubuntu/Debian و مسیر `/opt/birthday-bot` است. کد را از مخزن خودت روی VPS دریافت کن؛ فایل `.env` و دیتابیس را جداگانه منتقل کن، چون نباید در Git باشند.

```sh
sudo apt update
sudo apt install -y python3 python3-venv python3-pip nginx certbot python3-certbot-nginx git
sudo adduser --system --group --home /opt/birthday-bot --no-create-home birthdaybot
sudo install -d -o birthdaybot -g birthdaybot /opt/birthday-bot
git clone YOUR_REPOSITORY_SSH_OR_HTTPS_URL /tmp/birthday-bot-source
sudo cp -a /tmp/birthday-bot-source/. /opt/birthday-bot/
sudo chown -R birthdaybot:birthdaybot /opt/birthday-bot
sudo -u birthdaybot python3 -m venv /opt/birthday-bot/.venv
sudo -u birthdaybot /opt/birthday-bot/.venv/bin/pip install -r /opt/birthday-bot/requirements.txt
```

اگر مخزن خصوصی است، قبل از `git clone` دسترسی GitHub را برای حساب SSH خودت تنظیم کن. اگر پروژه از قبل در `/opt/birthday-bot` است، `git clone` و کپی را رد کن؛ فایل‌های `.env` و دیتابیس را هرگز با کد جایگزین نکن.

### ۲. انتقال امن دیتابیس فعلی

بات را روی کامپیوتر قدیمی متوقف کن تا چیزی در دیتابیس ننویسد. از SQLite backup API یک کپی سازگار بساز؛ این کار WAL را هم درست در نظر می‌گیرد:

```powershell
py -3.12 -c "import sqlite3; src=sqlite3.connect('birthdays.db'); dst=sqlite3.connect('birthdays-transfer.db'); src.backup(dst); dst.close(); src.close()"
scp .\birthdays-transfer.db YOUR_SSH_USER@YOUR_VPS:~/birthdays-transfer.db
```

با حساب SSH خودت وارد VPS شو و فایل را با مالکیت سرویس نصب کن:

```sh
sudo install -o birthdaybot -g birthdaybot -m 600 "$HOME/birthdays-transfer.db" /opt/birthday-bot/birthdays.db
rm "$HOME/birthdays-transfer.db"
```

فایل `.env` را جداگانه از حساب SSH خودت منتقل و نصب کن؛ آن را داخل مخزن قرار نده:

```powershell
scp .\.env YOUR_SSH_USER@YOUR_VPS:~/.env-upload
```

سپس روی VPS:

```sh
sudo install -o birthdaybot -g birthdaybot -m 600 "$HOME/.env-upload" /opt/birthday-bot/.env
rm "$HOME/.env-upload"
```

در `.env` روی VPS تنظیمات فعلی رباتت را نگه دار و این مقادیر را تنظیم کن:

```dotenv
DB_PATH=/opt/birthday-bot/birthdays.db
WEBAPP_URL=https://YOUR_DOMAIN/
WEBAPP_API_HOST=127.0.0.1
WEBAPP_API_PORT=8080
WEBAPP_API_ALLOWED_ORIGINS=
```

`YOUR_DOMAIN` را با دامنه‌ای عوض کن که به IP سرور اشاره می‌کند. آدرس HTTPS را به شکل `https://your-domain/` بنویس. چون سایت و API هم‌مبدأ هستند، `webapp/api-config.js` را تغییر نده و دامنهٔ دیگری در CORS اضافه نکن.

### ۳. راه‌اندازی سرویس ربات و مینی‌اپ

فایل نمونهٔ [birthday-bot.service](deploy/birthday-bot.service) از همین مسیرها استفاده می‌کند. برنامه `.env` را از کنار `main.py` می‌خواند. اگر مسیر یا نام کاربر را تغییر دادی، `User`, `Group`, `WorkingDirectory`, `ExecStart` و `ReadWritePaths` را با آن هماهنگ کن.

```sh
sudo cp /opt/birthday-bot/deploy/birthday-bot.service /etc/systemd/system/birthday-bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now birthday-bot
sudo systemctl status birthday-bot
curl http://127.0.0.1:8080/health
```

پاسخ health باید `{"ok": true}` باشد. آدرس `/` خود مینی‌اپ را می‌دهد؛ فایل‌های استاتیک فقط از `webapp/` سرو می‌شوند. فایل `.env`، دیتابیس، بکاپ‌ها و بقیهٔ سورس‌ها در مسیر استاتیک نیستند.

### ۴. HTTPS با Nginx

در DNS یک رکورد A برای دامنه به IP VPS بگذار و پورت‌های 80 و 443 را در firewall باز کن. فایل HTTP موقت [nginx-birthday-bot-http.conf](deploy/nginx-birthday-bot-http.conf) را نصب کن؛ `bot.example.com` را با دامنه‌ات جایگزین کن:

```sh
sudo cp /opt/birthday-bot/deploy/nginx-birthday-bot-http.conf /etc/nginx/sites-available/birthday-bot
sudo sed -i 's/bot.example.com/YOUR_DOMAIN/g' /etc/nginx/sites-available/birthday-bot
sudo ln -s /etc/nginx/sites-available/birthday-bot /etc/nginx/sites-enabled/birthday-bot
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d YOUR_DOMAIN --redirect
```

Certbot گواهی را می‌گیرد و پیکربندی HTTPS را می‌سازد. اگر ترجیح می‌دهی فایل نهایی را خودت مدیریت کنی، پس از صدور گواهی نمونهٔ [nginx-birthday-bot.conf](deploy/nginx-birthday-bot.conf) را نصب و دامنه را جایگزین کن. بعد:

```sh
sudo nginx -t
sudo systemctl reload nginx
curl https://YOUR_DOMAIN/health
```

اکنون `https://YOUR_DOMAIN/` باید مینی‌اپ را باز کند. بات باید با همین `WEBAPP_URL` در حال اجرا باشد تا دکمهٔ «تبدیل تاریخ» در تلگرام آدرس جدید را بگیرد؛ اگر `.env` را بعد از شروع سرویس تغییر دادی، `sudo systemctl restart birthday-bot` بزن. اگر قبلاً Main Mini App را در BotFather تنظیم کرده‌ای، نشانی آن را هم به همین URL تغییر بده.

مینی‌اپ را از دکمهٔ inline داخل گفت‌وگوی خصوصی بات باز کن تا تلگرام `initData` امضاشده و اطلاعات پروفایل را بفرستد. API بات امضا را بررسی می‌کند و پروفایل، تولد خودت و فهرست عزیزان را فقط با شناسهٔ همان کاربر می‌خواند یا تغییر می‌دهد. ذخیرهٔ تولد از مینی‌اپ نیز از همین API انجام می‌شود؛ سال فقط در مرورگر برای اعتبارسنجی می‌ماند و بات ماه و روز را نگه می‌دارد. دکمهٔ قدیمی reply keyboard همچنان برای سازگاری با `sendData` پشتیبانی می‌شود.

دکمهٔ «امروز» و شمارش روزها بر اساس `Asia/Tehran` است تا با `TIMEZONE` پیش‌فرض بات هماهنگ باشد. اگر `TIMEZONE` را در `.env` تغییر می‌دهی، شناسهٔ منطقهٔ زمانی را هم در `webapp/calendar.js` در تابع `todaySerial()` هماهنگ کن.

## امکانات کاربران

- ثبت و ویرایش تولد شمسی با دکمه‌های رنگی؛ شمارش روزهای گذشته و باقی‌مانده.
- فعال/غیرفعال کردن اعلان شخصی؛ ارسال پیام به پشتیبانی.
- `/start`، `/help`، `/id`، `/mybirthday`، `/setbirthday ماه روز`، `/deletebirthday` و `/cancel`.
- حذف تولد پس از تأیید؛ اعلان کاربر بلاک‌شده ارسال نمی‌شود.
- تولد ۳۰ اسفند در سال غیرکبیسه در ۲۹ اسفند محاسبه می‌شود.
- بخش «تولد عزیزان»: افزودن، صفحه‌بندی (هر صفحه ۵ نفر)، روشن/خاموش کردن یادآوری هر نفر یا همهٔ عزیزان و حذف با تأییدیه.
- در مینی‌اپ: پروفایل و عکس تلگرام، شناسهٔ کاربری، تولد خود، تبدیل تاریخ شمسی/میلادی/قمری ام‌القری، و مدیریت تولدهای عزیزان.

## پنل ادمین

در گفتگوی خصوصی `/admin` یا دکمه «پنل مدیریت» را بزنید. دسترسی تمام مسیرهای مدیریت در سمت سرور بررسی می‌شود.

- آمار کاربران خصوصی، ثبت تولد، تولد امروز/ماه شمسی، ورود و فعالیت امروز/۷ روز اخیر، پیام‌ها و کلیک‌ها، گروه‌ها و گزارش ارسال.
- فهرست صفحه‌بندی‌شده و جستجوی شناسه کاربر؛ مسدود/آزاد کردن کاربر و تغییر اعلان شخصی.
- قفل کانال: تغییر کانال عمومی (`@channel`) یا خصوصی (`-100... https://t.me/+...`) و روشن/خاموش کردن قفل. ربات باید ادمین کانال باشد. خطای بررسی عضویت موجب عبور از قفل نمی‌شود.
- ارسال همگانی یا به یک کاربر: متن، عکس، ویدیو، فایل، صدا، استیکر. پیش‌نمایش و تأیید الزامی است. کاربر باید قبلاً ربات را استارت کرده باشد.
- صف ارسال پایدار، شمارش موفق/ناموفق، رعایت محدودیت سرعت و `RetryAfter`، توقف باقی ارسال‌ها و ادامه صف پس از راه‌اندازی دوباره.
- دکمه «🔁 تلاش مجدد ناموفق‌ها» در گزارش ارسال‌ها: تحویل‌های ناموفق دوباره در صف قرار می‌گیرند.
- تنظیم متن خوشامد، سرعت ارسال (۱ تا ۲۵ در ثانیه)، حالت تعمیر، اعلان ورود کاربران، ساعت یادآوری و فعال‌سازی ایموجی پریمیوم.
- کلیدواژه‌های پاسخ تاریخ در گروه از «تنظیمات» قابل تغییر است (پیش‌فرض: `تاریخ,تولدم,تولد من`).
- افزودن/حذف ادمین فقط توسط مالکان `.env` و پس از تأیید. مالک اصلی از پنل قابل حذف نیست.
- خروجی CSV کاربران و ثبت گزارش عملیات مدیریتی.

یادآوری روزانه و اعلان ورود کاربران ابتدا **خاموش** هستند؛ از «تنظیمات» فعال کنید. اگر ساعت روز گذشته باشد، فعال‌سازی یادآوری باعث ارسال یادآوری همان روز می‌شود. هنگام خاموش بودن یادآوری عمومی، تنظیم اعلان شخصی ذخیره می‌ماند.

ایموجی‌های متن پیام‌ها و کپشن‌ها به آیکن‌های پریمیوم تعریف‌شده در `ui.py` تبدیل می‌شوند. عنوان دکمه‌ها بدون ایموجی معمولی و آیکن آن‌ها با `icon_custom_emoji_id` نمایش داده می‌شود. دکمهٔ «تولد عزیزان» قرمز و دارای آیکن پریمیوم تولد است. تلگرام باید استفاده از ایموجی پریمیوم را برای بات مجاز بداند؛ در صورت رد درخواست، آیکن حذف و درخواست بدون جایگزین معمولی تکرار می‌شود. پیام‌های کوتاه callback بدون ایموجی هستند. رنگ‌ها مطابق قابلیت کلاینت تلگرام نمایش داده می‌شوند.

## دریافت پیام گروه‌ها

ربات را به گروه اضافه کنید. برای دریافت همه پیام‌های کاربران، ربات باید ادمین باشد یا Privacy Mode در BotFather خاموش شود. بعد از تغییر Privacy Mode ممکن است نیاز باشد ربات از گروه خارج و دوباره اضافه شود.

- پنل «گروه‌ها و پیام‌ها» متن/کپشن و فرستنده را نمایش می‌دهد؛ اصل رسانه با دکمه مشاهده، در صورت دسترسی تلگرام، کپی می‌شود.
- فقط پیام‌های دریافتی از زمان اجرای نسخه جدید ثبت می‌شوند؛ تاریخچه پیش از آن قابل بازیابی نیست.
- آخرین ۱۰۰۰ پیام هر گروه نگه داشته می‌شود. آمار پیام‌های دریافت‌شده جدا از این سقف است. ویرایش پیام، متن ثبت‌شده را به‌روز می‌کند.
- مدیر ربات می‌تواند ثبت را عمومی یا برای هر گروه خاموش کند.
- مدیر گروه با `/groupmonitor off` یا `/groupmonitor on` ثبت را کنترل می‌کند. `/groupprivacy` توضیح قابلیت و `/id` شناسه گروه را نمایش می‌دهد.
- پیام‌های گروه، کاربران خصوصی ربات محسوب نمی‌شوند و هدف ارسال همگانی قرار نمی‌گیرند.

## داده‌ها و محدودیت‌ها

در نخستین اجرا، اطلاعات `birthdays.json` و جدول قدیمی `users` بدون حذف منابع به جدول جدید `bot_users` در SQLite منتقل می‌شوند. تنظیمات، صف، گزارش عملیات و پیام‌های گروه در همان دیتابیس ذخیره می‌شوند. پس از انتقال، فایل JSON دیگر منبع فعال اطلاعات نیست.

از این نسخه به بعد `birthdays.db` و `birthdays.json` در گیت نگهداری **نمی‌شوند**؛ مخزن عمومی است و این فایل‌ها داده واقعی کاربران را دارند. اگر سروری این فایل‌ها را هنوز tracked دارد، بعد از `git pull` این نسخه، فایل‌ها از working tree حذف می‌شوند؛ **قبل از pull روی سرور یک کپی از `birthdays.db` بگیرید**. برای همین، اگر فایل دیتابیس وجود نداشته باشد ولی بکاپی در `backups/automatic/` باشد، بات با پیام خطای واضح بالا نمی‌آید تا نسخه پشتیبان را به مسیر `DB_PATH` برگردانید و دیتا با دیتابیس خالی جایگزین نشود. مسیر نسبی در `DB_PATH` همیشه نسبت به پوشه پروژه باز می‌شود، نه پوشه جاری اجرا. قبل از جابه‌جایی دیتابیس، ربات را متوقف کنید یا از قابلیت backup خود SQLite استفاده کنید؛ در حالت WAL کپی تنها فایل `.db` هنگام اجرا کافی نیست.

آمار فعالیت از زمان نصب این نسخه محاسبه می‌شود. زمان ورود کاربران قدیمی که قبلاً ذخیره نشده نامعلوم است. «بلاک تلگرام» تنها هنگام شکست ارسال شناسایی می‌شود. آمار کاربران شامل کسانی است که ربات دیده است، نه کاربران ناشناخته یا اعضای کانال.

اگر برنامه دقیقاً بعد از ارسال موفق و قبل از ثبت نتیجه متوقف شود، آن پیام ممکن است هنگام بازیابی صف دوباره ارسال شود؛ Telegram Bot API برای `copyMessage` تضمین ارسال دقیقاً یک‌بار ارائه نمی‌کند. مکالمه نیمه‌تمام پنل در حافظه است؛ بعد از راه‌اندازی دوباره از `/admin` شروع کنید. پیش‌نمایش‌ها و صف تأییدشده در دیتابیس باقی می‌مانند.

## مدیریت سرویس روی سرور

برای انتقال یکپارچهٔ بات و مینی‌اپ، از دستورهای بخش Linux VPS و فایل systemd داخل `deploy/` استفاده کن. وضعیت و گزارش زنده:

```sh
sudo systemctl status birthday-bot
journalctl -u birthday-bot -f
```

برای پاک‌سازی کامل داده‌ها از تاریخچه گیت (چون قبلاً commit شده‌اند) به `git filter-repo` و سپس force-push نیاز است؛ قبل از آن با همه همکاران هماهنگ کنید.

## ساختار فعال

`main.py` مسیر کاربر/گروه و راه‌اندازی، `admin_panel.py` پنل، `store.py` داده‌ها، `ui.py` دکمه‌ها و ایموجی، `calendar_utils.py` تاریخ، `runtime_jobs.py` صف ارسال و یادآوری.

## بررسی

تست‌ها از تلگرام شبیه‌سازی‌شده و دیتابیس موقت استفاده می‌کنند و پیام واقعی ارسال نمی‌کنند:

```sh
.venv/bin/python -m unittest discover -s tests -t . -v
.venv/bin/python -m pip install ruff
.venv/bin/ruff check .
```

گردش‌کار `Tests` در `.github/workflows/tests.yml` همین دو دستور را روی هر push به `main` و هر pull request اجرا می‌کند.

تست‌ها به `BOT_TOKEN` واقعی نیاز ندارند؛ ماژول `tests/__init__.py` پیش از ایمپورت `config` یک توکن ساختگی و `ADMIN_IDS` آزمایشی تنظیم می‌کند و هر تست روی یک فایل SQLite موقت اجرا می‌شود.
